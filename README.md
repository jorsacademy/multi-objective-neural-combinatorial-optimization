# Multi-Objective Neural Combinatorial Optimization

[![CI](https://github.com/jorsacademy/multi-objective-neural-combinatorial-optimization/actions/workflows/ci.yml/badge.svg)](https://github.com/jorsacademy/multi-objective-neural-combinatorial-optimization/actions/workflows/ci.yml)
[![Python 3.11–3.12](https://img.shields.io/badge/python-3.11%20%7C%203.12-blue)](https://www.python.org/)
[![License: PolyForm Noncommercial 1.0.0](https://img.shields.io/badge/license-PolyForm%20Noncommercial%201.0.0-orange)](LICENSE)

A verification-first research implementation for **neural Pareto-set approximation** on bi-objective 0-1 knapsack. The repository compares two single-model conditioning strategies under the same inference-query budget:

- normalized weighted-sum preferences, which naturally target supported Pareto points;
- epsilon constraints, which can address unsupported points on non-convex discrete fronts.

Every training label and evaluation reference is generated by an exact Pareto dynamic program. Neural outputs are feasible heuristic candidates, not certificates of Pareto optimality or frontier completeness.

## Research question

> Under a fixed number of test-time queries, does epsilon-constraint conditioning recover more of the exact discrete Pareto frontier—especially unsupported points—than weighted-sum preference conditioning, and does either learned policy improve hypervolume, coverage, or diversity over matched density heuristics under size and distribution shift?

The benchmark separates four issues that are often conflated:

1. **Conditional imitation:** can one permutation-equivariant model map many trade-off conditions to their canonical exact solutions?
2. **Set quality:** do repeated queries produce a high-hypervolume nondominated set rather than duplicate solutions?
3. **Discrete-front coverage:** are unsupported Pareto points recovered, or only convex-hull-supported trade-offs?
4. **Generalization:** do the same parameters transfer to larger instances and shifted objective relationships?

## Claims boundary

This is a compact synthetic methodology benchmark. It does **not** claim:

- a state-of-the-art multi-objective knapsack solver;
- exact Pareto-front generation by a neural network;
- that epsilon conditioning is universally superior to decomposition;
- transfer to arbitrary objective counts or combinatorial domains;
- hardware-independent speedup over exact dynamic programming;
- industrial-scale frontier enumeration;
- calibrated preferences or guarantees for unseen conditions;
- an OSI-approved open-source license.

The frozen protocol is designed to expose duplicate outputs, unsupported-point blind spots, feasibility failures, and extrapolation degradation rather than hide them behind one aggregate score.

## Optimization problem

For positive integer weights \(w_i\), two positive integer profits \(p_i^{(1)},p_i^{(2)}\), and capacity \(C\), the feasible set is

\[
\mathcal X =
\left\{
 x\in\{0,1\}^n:
 \sum_{i=1}^{n}w_i x_i\le C
\right\}.
\]

The objective vector is

\[
f(x)=
\left(
\sum_{i=1}^{n}p_i^{(1)}x_i,
\sum_{i=1}^{n}p_i^{(2)}x_i
\right),
\]

and both coordinates are maximized. A feasible solution \(x\) dominates \(y\) when it is no worse in either objective and strictly better in at least one. The exact Pareto frontier contains the objective vectors of all nondominated feasible selections.

## Exact Pareto oracle

The oracle uses a capacity-indexed dynamic program. For each item prefix and capacity, it keeps a canonical set of mutually nondominated objective vectors. Skip and take states are merged, duplicate objective vectors retain the lower-weight and then lexicographically smaller selection, and dominated states are removed.

For small instances, a second oracle enumerates all \(2^n\) subsets and compares the complete canonical frontier. Corpus loading also recomputes the frontier instead of trusting stored labels.

```text
positive-integer instance
          │
          ▼
capacity-indexed Pareto dynamic program
          │
          ├── canonical exact frontier
          ├── weighted-sum labels
          ├── epsilon-constraint labels
          └── hypervolume / coverage reference
```

See [`docs/exactness.md`](docs/exactness.md) for the exact/approximate boundary.

## Why compare weighted sums and epsilon constraints?

A normalized weighted-sum query uses \(\lambda\in[0,1]\):

\[
\max_{x\in\mathcal X}
\lambda\frac{f_1(x)}{z_1^\star}
+
(1-\lambda)\frac{f_2(x)}{z_2^\star},
\]

where \(z^\star\) is the exact per-instance ideal point. Weighted sums can select weakly supported points: points that maximize some nonnegative linear scalarization. Discrete Pareto fronts can also contain **unsupported** points below the upper convex envelope; no weighted-sum preference makes such a point uniquely optimal.

The epsilon-conditioned oracle instead solves

\[
\max_{x\in\mathcal X} f_1(x)
\quad\text{subject to}\quad
\frac{f_2(x)}{z_2^\star}\ge \epsilon.
\]

Sweeping \(\epsilon\) can target supported and unsupported frontier regions. The repository classifies supportedness by exact rational weight-interval feasibility, not by a finite preference grid.

The use of exact ideal-point normalization is part of the controlled oracle benchmark and is reported explicitly. It should not be interpreted as a deployment-free assumption; practical systems may need exact scalar anchors or estimates.

## Conditional neural policies

Both learned methods use the same `ConditionalParetoPolicy` architecture. It is a permutation-equivariant DeepSets-style network:

1. each item is encoded from normalized weight, profit, and density features;
2. the scalar query is embedded into a four-dimensional condition representation;
3. local item embeddings are pooled by mean and maximum;
4. local, global, and condition representations produce one inclusion logit per item.

The parameter count does not depend on item count. The weighted-sum and epsilon variants differ only in condition semantics and exact labels, not model capacity.

### Weighted-sum policy

The condition is \(\lambda\). Labels are deterministic exact normalized weighted-sum optima. Ties use a reproducible balance/sum/weight/selection rule.

### Epsilon-constraint policy

The condition is the required normalized second-objective floor \(\epsilon\). Labels maximize objective 1 among exact Pareto points meeting the floor. Training conditions combine a uniform grid with exact-front thresholds so the model sees discrete transitions between Pareto solutions.

## Deterministic feasible decoding

A neural logit vector is not accepted as a solution. Decoding constructs several score-dependent greedy candidates, performs deterministic one-add/one-swap local improvement, and selects the best candidate under the relevant condition criterion. Every reported candidate is then audited by recomputing:

- binary decisions;
- total weight;
- both objective values;
- capacity feasibility;
- internal objective consistency.

The decoder never claims that its output is nondominated. Nondominance is established only by exact pairwise filtering of the finite candidate set produced by the query budget.

## Matched baselines

Four fixed-budget methods are reported:

| Method | Query semantics | Candidate source |
| --- | --- | --- |
| `weighted_sum_density` | weighted-sum grid | conditioned profit-density heuristic |
| `epsilon_constraint_density` | epsilon grid | objective-floor-oriented density heuristic |
| `weighted_sum_policy` | weighted-sum grid | learned weighted policy |
| `epsilon_constraint_policy` | epsilon grid | learned epsilon policy |

All methods receive the same number of queries. Duplicate candidate objective vectors are retained for query-efficiency accounting but removed before Pareto indicators are computed.

## Metrics

### Exact-front structure

- exact frontier size;
- supported-point fraction;
- number of instances containing unsupported points.

### Approximate set quality

- normalized hypervolume ratio against reference point \((0,0)\);
- unary additive epsilon indicator;
- normalized IGD+;
- exact objective-vector coverage;
- unsupported objective-vector coverage;
- extreme-point recovery.

### Diversity and efficiency

- approximate nondominated frontier size;
- unique candidate count;
- nondominated yield per query;
- epsilon-condition satisfaction rate;
- feasibility rate;
- wall-clock construction time;
- paired bootstrap interval for hypervolume gain over weighted-density guidance.

No weighted composite score merges quality, coverage, diversity, and runtime.

## Controlled generalization protocol

Training item counts are \(n\in\{8,10,12,14\}\). Training includes independent, aligned, and weakly conflicting objectives. Disjoint deterministic seeds are used for training, validation, and all evaluation scenarios.

The frozen protocol evaluates:

1. `interpolation` — nominal 12-item independent instances;
2. `size_18` — item-count extrapolation;
3. `size_24` — harder item-count extrapolation;
4. `tight_capacity` — approximately 25% of total weight;
5. `loose_capacity` — approximately 65% of total weight;
6. `strong_conflict` — a larger unsupported-frontier stress test;
7. `aligned_objectives` — nearly coincident objectives and small fronts;
8. `heavy_tail` — Pareto-like profit distributions;
9. `clustered_tradeoffs` — two item clusters favoring opposite objectives;
10. `value_scale_shift` — profits well outside the training scale.

Evaluation regimes and seeds are never used to fit either model.

## CLI

### Generate one exact-labeled instance

```bash
mopareto generate \
  --item-count 12 \
  --regime strongly_conflicting \
  --seed 42 \
  --output artifacts/example.json
```

See `mopareto generate --help` for all supported regimes.

### Build deterministic corpora

```bash
mopareto collect \
  --count 80 \
  --item-counts 8 10 12 14 \
  --regimes independent aligned weakly_conflicting \
  --seed 3100 \
  --output artifacts/train.jsonl

mopareto collect \
  --count 24 \
  --item-counts 8 10 12 14 \
  --regimes independent aligned weakly_conflicting \
  --seed 4100 \
  --output artifacts/validation.jsonl
```

### Verify one frontier by enumeration

```bash
mopareto oracle artifacts/validation.jsonl \
  --sample-index 0 \
  --output artifacts/oracle-check.json
```

### Train the weighted-sum policy

```bash
mopareto train artifacts/train.jsonl \
  --validation artifacts/validation.jsonl \
  --model weighted_sum \
  --epochs 30 \
  --checkpoint artifacts/weighted-sum-policy.safetensors \
  --output-report artifacts/weighted-training.json
```

### Train the epsilon-constraint policy

```bash
mopareto train artifacts/train.jsonl \
  --validation artifacts/validation.jsonl \
  --model epsilon_constraint \
  --epochs 30 \
  --checkpoint artifacts/epsilon-constraint-policy.safetensors \
  --output-report artifacts/epsilon-training.json
```

### Compare fixed-budget Pareto sets

```bash
mopareto benchmark artifacts/test.jsonl \
  --weighted-checkpoint artifacts/weighted-sum-policy.safetensors \
  --epsilon-checkpoint artifacts/epsilon-constraint-policy.safetensors \
  --scenario size_24 \
  --query-budget 21 \
  --output-json artifacts/benchmark.json \
  --output-csv artifacts/benchmark.csv
```

### Run the frozen research protocol

```bash
mopareto research \
  --config configs/research_v1.json \
  --checkpoint-directory artifacts/checkpoints \
  --output-report artifacts/research-report.json
```

## Methodological limitations

Bi-objective knapsack has a pseudo-polynomial exact dynamic program, making complete frontier labels practical only for controlled capacities and moderate fronts. Frontier size can still grow rapidly. The implementation is intentionally not optimized as a production multiobjective solver.

A finite query grid can miss exact points even when the conditional oracle family is theoretically capable of targeting them. Weighted-sum failure on unsupported points is a property of linear scalarization, while epsilon-policy failure may instead reflect condition discretization, model error, or decoder error. The benchmark reports these mechanisms separately where possible.

Canonical labels choose one selection when multiple feasible subsets share an objective vector or condition optimum. Selection-level training can therefore penalize an alternative subset with identical objectives even though set-level evaluation treats objective-equivalent outcomes as identical.

Hypervolume depends on normalization and reference point. This repository uses the exact per-instance ideal point and reference \((0,0)\), and reports other indicators so conclusions do not rest on hypervolume alone.

## Research context

The implementation is positioned relative to:

- Lin, Yang, and Zhang, [“Pareto Set Learning for Neural Multi-objective Combinatorial Optimization”](https://arxiv.org/abs/2203.15386), which trains a single preference-conditioned model to approximate Pareto sets;
- Chen et al., [“Neural Multi-Objective Combinatorial Optimization with Diversity Enhancement”](https://proceedings.neurips.cc/paper_files/paper/2023/hash/7b5ae891000049b91b3b62de596b1560-Abstract-Conference.html), which highlights duplicate-solution and diversity limitations of decomposition-based neural methods;
- Lu et al., [“Context-aware Diversity Enhancement for Neural Multi-Objective Combinatorial Optimization”](https://arxiv.org/abs/2405.08604), which links preference conditioning with hypervolume-oriented diversity;
- Fan et al., [“Preference-Driven Multi-Objective Combinatorial Optimization with Conditional Computation”](https://proceedings.neurips.cc/paper_files/paper/2025/hash/10fc83943b4540a9524af6fc67a23fef-Abstract-Conference.html), which adapts model computation across preference subproblems;
- Singh et al., [“Divide and Learn: Multi-Objective Combinatorial Optimization at Scale”](https://arxiv.org/abs/2602.11346), which studies scalable online learning over decomposed decision spaces.

This repository is not a reproduction of any one paper. Its narrower contribution is a **fully exact discrete-front audit** of weighted-sum versus epsilon conditioning, including exact weak-supportedness classification and direct measurement of unsupported-point recovery.
